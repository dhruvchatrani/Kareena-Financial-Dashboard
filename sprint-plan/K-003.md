## Description

The function `clean_numeric()` is defined identically in two files (`processor.py:10-20` and `data_processor.py:11-20`). This violates DRY — any change to the parsing logic (e.g., adding a new currency symbol, changing error handling) must be made in two places, and they will inevitably diverge.

## Current Behaviour

Two identical copies of:

```python
def clean_numeric(val):
    if pd.isna(val) or val == '':
        return 0.0
    val_str = str(val).replace('₹', '').replace(',', '').strip()
    if val_str.startswith('(') and val_str.endswith(')'):
        val_str = '-' + val_str[1:-1]
    try:
        return float(val_str)
    except ValueError:
        return 0.0
```

## Expected Behaviour

Single shared copy imported by both consumers.

## Files to Modify

| File | Action |
|------|--------|
| Create `utils.py` | New file containing `clean_numeric()` |
| `processor.py` | Remove local definition, add `from utils import clean_numeric` |
| `data_processor.py` | Remove local definition, add `from utils import clean_numeric` |

## Steps to Implement

1. Create `utils.py` with the single `clean_numeric()` definition.
2. In `processor.py`:
   - Delete lines 10-20
   - Add `from utils import clean_numeric` at the top
3. In `data_processor.py`:
   - Delete lines 11-20
   - Add `from utils import clean_numeric` at the top (replace `pd` usage — `pd.isna` in the function should be replaced with a try/except or pass the raw value)
   - **Note:** The function uses `pd.isna(val)`. The extracted version should still import pandas, or handle the check differently (e.g., `val is None or val == ''`).
4. Run the application and verify all upload and calculation flows still work.
