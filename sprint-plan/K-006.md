# K-006: Clean up unused `static/` mount and `archive/` reference debt

**Priority:** P3-Cleanup  
**Sprint:** 1  
**Estimate:** 30 minutes  
**Type:** Chore  
**Filed by:** Code audit  
**Components:** `main.py`

---

## Description

The `static/` directory is empty but is mounted as a FastAPI static files mount in `main.py:38`. Additionally, `archive/api_connector.py` is dead code that references the same env vars as the live `.env`, creating a stale reference surface.

## Current Behaviour

- `app.mount("/static", ...)` serves an empty directory
- `archive/api_connector.py` exists with live credential references but is never imported

## Expected Behaviour

- Remove the static mount (or add a comment explaining why it's kept)
- Add a `README.md` inside `archive/` explaining why the SP-API client was archived, so future developers don't waste time trying to integrate it

## Files to Modify

| File | Action |
|------|--------|
| `main.py` | Remove or comment `app.mount` on line 38 |
| `archive/README.md` | New file (or append note to existing) |

## Steps to Implement

1. In `main.py`, decide:
   - If static files are genuinely needed later, keep the mount but add a comment
   - If not, remove line 38 entirely
2. Create `archive/README.md`:
   ```markdown
   # Archived: Amazon SP-API Client

   This client was written to pull financial events and inventory data
   directly from Amazon's Selling Partner API. It has been superseded
   by the file-upload workflow (processor.py + upload-manual route).

   The file is kept for reference if live API integration is revisited.
   ```
3. Verify `ruff check .` passes after changes.

## Acceptance Criteria

- [ ] No empty directory is mounted as a static file server
- [ ] `archive/` has a README explaining its contents are legacy
- [ ] Application starts correctly
