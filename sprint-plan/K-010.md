# K-010: Wrap multi-file upload in a DB transaction

**Priority:** P2-Important  
**Sprint:** 2  
**Estimate:** 4 hours  
**Type:** Improvement  
**Filed by:** Code audit  
**Components:** `main.py` (upload-manual), `processor.py`

---

## Description

The `/upload-manual` route processes 5 files sequentially. If file 3 fails, files 1 and 2 have already committed their data to the database. This leaves the system in a partially-loaded state — incomplete data for the month with no easy way to detect the inconsistency.

## Current Behaviour

```python
# Settlement commits
count = processor.sync_settlement_csv(path, db, ...)  # commits internally
db.commit()  # commits again

# If Business CSV fails next, Settlement data is already in DB
```

Each processor function calls `db_session.commit()` internally, so there's no way to roll back everything if one file fails.

## Expected Behaviour

All files for a month should be loaded in a single database transaction. If any file fails, all changes for that upload session are rolled back.

## Steps to Implement

1. Refactor processor functions to **not** call `db.commit()` themselves — accept a `db` session and let the caller manage the transaction.

2. In `main.py`, wrap the entire upload block in a try/except with explicit rollback:
   ```python
   try:
       # Process all files (no internal commits)
       if settlement: processor.sync_settlement_csv(path, db, ...)
       if deferred: processor.sync_settlement_csv(path, db, ...)
       if business: processor.sync_business_csv(path, db, ...)
       if ads: processor.sync_ads_report(path, db, ...)
       if returns: processor.sync_returns_xml(path, db, ...)
       
       # All succeeded — commit once
       db.commit()
   except Exception as e:
       db.rollback()
       raise
   ```

3. Remove all `db.commit()` calls from within processor functions (keep `db.flush()` if needed for identity maps).

4. Handle the scoped delete within the same transaction (delete old data, insert new, commit all or nothing).

## Acceptance Criteria

- [ ] Uploading 5 files where one fails → no data from any file persists in DB
- [ ] Uploading 5 files where all succeed → all data persists correctly
- [ ] No processor function calls `db.commit()` internally
- [ ] All existing upload functionality works
