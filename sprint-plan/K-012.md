# K-012: Add confirmation guard to `/admin/reset-db`

**Priority:** P1-MustHave  
**Sprint:** 3  
**Estimate:** 3 hours  
**Type:** Security  
**Filed by:** Code audit  
**Components:** `main.py`, `templates/admin.html`

---

## Description

The `/admin/reset-db` endpoint accepts a single POST request and immediately deletes all records from 7 tables (`FinancialEvent`, `Inventory`, `COGS`, `OperatingExpense`, `SyncLog`, `AdsMetric`, `BusinessMetric`). There is no confirmation dialog, no "type CONFIRM to proceed" step, and no undo. A single errant click or CSRF-like request can destroy all financial data.

## Current Behaviour

```python
@app.post("/admin/reset-db")
async def reset_db(request: Request, db: Session = Depends(get_db)):
    for model in [...]:
        db.query(model).delete()
    db.commit()
    return RedirectResponse(url="/admin?msg=Database+Reset+Successful", status_code=303)
```

## Expected Behaviour

The reset should require a two-step confirmation:
1. User clicks "Reset Database" button
2. A confirmation prompt appears asking them to type "RESET" to proceed
3. The POST includes the confirmation token

## Steps to Implement

1. Add a required form field `confirm_text` to the reset form in `admin.html`:
   ```html
   <form action="/admin/reset-db" method="post" onsubmit="return confirm('Are you sure? Type RESET in the prompt')">
       <label>Type "RESET" to confirm: <input type="text" name="confirm_text" required pattern="RESET"></label>
       <button type="submit" class="bg-red-600 text-white px-4 py-2 rounded">Delete All Data</button>
   </form>
   ```

2. In `main.py`, validate the confirmation:
   ```python
   @app.post("/admin/reset-db")
   async def reset_db(request: Request, confirm_text: str = Form(...), db: Session = Depends(get_db)):
       if confirm_text != "RESET":
           return HTMLResponse("Confirmation text must be exactly 'RESET'.", status_code=400)
       # ... proceed with reset
   ```

3. Add a second guard: require the user to also provide their password (if auth is implemented from K-011) to confirm identity.

4. Update the success/error messages in the response.

## Acceptance Criteria

- [ ] POST to `/admin/reset-db` without `confirm_text=RESET` returns 400
- [ ] POST with `confirm_text=RESET` performs the reset
- [ ] The admin page has a clear text input (not just a JS confirm dialog)
- [ ] Success message is shown after reset
