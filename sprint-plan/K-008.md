# K-008: Set up Alembic for database migrations

**Priority:** P2-Important  
**Sprint:** 2  
**Estimate:** 6 hours  
**Type:** Infrastructure  
**Filed by:** Code audit  
**Components:** Project root, `models.py`, `database.py`

---

## Description

The database schema is currently created from scratch on every app startup via `Base.metadata.create_all()` in `main.py:31`. This means:
- Schema changes require manual SQLite surgery (DROP TABLE, ALTER TABLE)
- No version history of schema changes
- No rollback capability
- Production data loss if a migration goes wrong

## Current Behaviour

```python
models.Base.metadata.create_all(bind=engine)  # main.py:31
```

## Expected Behaviour

Alembic manages all schema changes with:
- Version-controlled migration scripts
- `upgrade()` and `downgrade()` functions
- An `alembic_version` table tracking current state
- The `create_all()` call replaced by Alembic's `stamp head` or run via migration

## Steps to Implement

1. Install Alembic: `pip install alembic`
2. Run `alembic init alembic`
3. Configure `alembic/env.py` to use the SQLAlchemy engine from `database.py` and import `Base` from `models.py`:
   ```python
   from database import engine
   from models import Base
   target_metadata = Base.metadata
   ```
4. Set `sqlalchemy.url` in `alembic.ini` or use env var.
5. Run `alembic revision --autogenerate -m "initial"` to create the first migration.
6. Run `alembic upgrade head` to apply it.
7. Update `main.py` to remove `Base.metadata.create_all()` — replace with `alembic upgrade head` called during startup (or document that migrations run separately).
8. Add `.ini` file and `alembic/` directory to version control.

## Acceptance Criteria

- [ ] `alembic history` shows at least one migration
- [ ] `alembic upgrade head` creates all tables
- [ ] `alembic downgrade -1` drops them cleanly
- [ ] Application starts and works with Alembic-managed schema
- [ ] No `create_all()` call remains in application code
