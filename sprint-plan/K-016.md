# K-016: Optimize SKU-insights endpoint — cache / consolidate DB queries

**Priority:** P2-Important  
**Sprint:** 4  
**Estimate:** 6 hours  
**Type:** Performance  
**Filed by:** Code audit  
**Components:** `main.py` (sku-insights route), `data_processor.py`

---

## Description

The `/sku-insights` route calls `calculate_sku_metrics()` four times in a single request:

```python
sku_df = dp.calculate_sku_metrics(db, parsed_start, parsed_end)       # Current
wow_df = dp.calculate_sku_metrics(db, wow_start, wow_end)             # +1
mom_df = dp.calculate_sku_metrics(db, mom_start, mom_end)             # +2
yoy_df = dp.calculate_sku_metrics(db, yoy_start, yoy_end)             # +3
```

Each call:
- Loads ALL financial events from the DB into memory (`query.all()`)
- Groups them by SKU with Pandas
- Queries COGS table
- Queries OpEx table

For a business with 12 months of data and 500 SKUs, this means loading 4× the data, performing 4× the aggregation work, and making 4× the DB queries. The 7-day WoW period overlaps significantly with the current period, compounding the waste.

## Current Behaviour

4 separate calls, each doing a full scan. Response time grows linearly with periods compared.

## Expected Behaviour

Use one of these strategies (pick the most appropriate):

**Option A (Recommended):** Load events once for the entire date range (current start → YoY end), filter in-memory for each sub-period. This reduces DB queries from 4 to 1.

**Option B:** Cache the `calculate_sku_metrics` result per date range in an in-memory LRU cache (e.g., `functools.lru_cache` or `cachetools.TTLCache`). Since date ranges may repeat during a session, this eliminates recomputation.

**Option C:** Pre-compute and store SKU metrics in a summary table, updated after each upload.

## Steps to Implement (Option A)

1. Refactor `calculate_sku_metrics` to accept pre-fetched events:
   ```python
   def calculate_sku_metrics(db, start_date=None, end_date=None, events=None):
       if events is None:
           query = db.query(models.FinancialEvent)
           if start_date and end_date:
               query = query.filter(...)
           events = query.all()
       # ... rest uses events
   ```

2. In the `/sku-insights` route, load events once for the widest range (YoY start → current end):
   ```python
   all_events = db.query(models.FinancialEvent).filter(
       models.FinancialEvent.posted_date >= yoy_start,
       models.FinancialEvent.posted_date <= parsed_end,
   ).all()
   
   sku_df = dp.calculate_sku_metrics(db, events=[e for e in all_events if parsed_start <= e.posted_date <= parsed_end])
   wow_df = dp.calculate_sku_metrics(db, events=[e for e in all_events if wow_start <= e.posted_date <= wow_end])
   # etc.
   ```
