# K-015: Add CSV encoding fallback mechanism

**Priority:** P2-Important  
**Sprint:** 3  
**Estimate:** 3 hours  
**Type:** Reliability  
**Filed by:** Code audit  
**Components:** `processor.py`

---

## Description

All CSV reading in `processor.py` uses `encoding='utf-8-sig'` hardcoded. If Amazon sends a file in a different encoding (e.g., `cp1252`, `latin-1`, `utf-16`), the file will fail to parse with a `UnicodeDecodeError` and the user gets a cryptic error message.

## Current Behaviour

```python
df = pd.read_csv(file_path, encoding='utf-8-sig')
```

And for format detection:
```python
with open(file_path, 'r', encoding='utf-8-sig') as f:
    lines = f.readlines()
```

## Expected Behaviour

Try `utf-8-sig` first, then fall back to common encodings. Log which encoding was used so format changes can be detected.

## Steps to Implement

1. Create a helper function in `utils.py`:
   ```python
   import chardet  # or use a try/except fallback without external deps
   
   ENCODING_FALLBACKS = ['utf-8-sig', 'utf-8', 'cp1252', 'latin-1', 'iso-8859-1', 'utf-16']
   
   def read_csv_with_fallback(file_path, **kwargs):
       """Try multiple encodings to read a CSV file."""
       for encoding in ENCODING_FALLBACKS:
           try:
               return pd.read_csv(file_path, encoding=encoding, **kwargs)
           except (UnicodeDecodeError, UnicodeError):
               continue
       raise ValueError(f"Could not read {file_path} with any supported encoding")
   ```

2. Replace all `pd.read_csv(file_path, encoding='utf-8-sig')` calls with the new helper.

3. Do the same for the format detection `open()` call in `_detect_csv_format()`.

4. Log which encoding succeeded for debugging.

**Note:** Adding `chardet` as a dependency would make this more robust but adds another package. The fallback chain without `chardet` is simpler and sufficient for Amazon's known encodings.

## Acceptance Criteria

- [ ] CSV files with `utf-8-sig` encoding continue to work
- [ ] CSV files with `cp1252` or `latin-1` encoding are parsed correctly
- [ ] The detected encoding is logged at INFO level
- [ ] A file with no supported encoding raises a clear error message
- [ ] Format detection also uses the fallback mechanism
