# K-007: Split `main.py` into modular route files

**Priority:** P2-Important  
**Sprint:** 2  
**Estimate:** 8 hours  
**Type:** Refactor  
**Filed by:** Code audit  
**Components:** `main.py`

---

## Description

`main.py` is 519 lines containing:
- App setup (lines 1–42)
- A model class (SettingsUpdate)
- 14 route handlers
- Inline helper functions
- Upload logic
- Admin logic
- Promotions logic

This makes it hard to navigate, test, and maintain. Every route change requires touching this single file, increasing merge conflicts and cognitive load.

## Current Behaviour

All routes and logic live in `main.py`.

## Expected Behaviour

Routes should be split into domain-specific modules:

```
routes/
  __init__.py      # App factory, shared deps
  dashboard.py     # GET /
  sku_insights.py  # GET /sku-insights
  advertising.py   # GET /advertising
  reconciliation.py# GET /reconciliation
  promotions.py    # GET /promotions, POST /promotions/add, /delete
  admin.py         # All /admin/* routes
  audit.py         # /audit, /upload-manual
  docs.py          # /docs
  settings.py      # /settings (GET + POST)
```

## Steps to Implement

1. Create `routes/__init__.py` with the FastAPI `APIRouter` setup and shared dependencies.
2. Create each route module as listed above, moving the corresponding route functions from `main.py`.
3. Update `main.py` to:
   ```python
   from routes.dashboard import router as dashboard_router
   from routes.admin import router as admin_router
   # ... etc
   app.include_router(dashboard_router)
   app.include_router(admin_router)
   ```
4. Keep app startup, template config, and static mount in `main.py`.
5. Move helper functions (`_parse_dates`, `_safe_date_prev_month`, etc.) to `utils.py`.
6. Test every route after the refactor.

## Acceptance Criteria

- [ ] `main.py` is reduced to < 80 lines (setup only)
- [ ] All 14+ routes work identically to before
- [ ] Each route module is < 150 lines
- [ ] `ruff check .` passes
- [ ] No circular imports
